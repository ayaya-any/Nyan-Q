## 版本亮点

- 支持通过配置或 JavaScript 脚本为 TUN 设置 `route-exclude-address`。列出的 IP/CIDR
  会真正绕过 TUN 虚拟网卡，而不仅是命中 `DIRECT` 规则。
- 支持块列表、行内列表、flow 映射、锚点/合并键等 YAML 写法；自动去重并校验每个
  条目，无效的 IP/CIDR 会在启动/热重载前给出明确错误，不再静默丢弃或把非法值交给内核。
- TUN 不再整段覆盖：`stack`、`mtu`、`strict-route`、`route-address`、
  `route-exclude-address`、`dns-hijack` 扩展、`udp-timeout`、`device` 等用户设置会合并
  保留；`enable`、`auto-route`、`auto-detect-interface` 和 DNS 劫持基础项仍由 Nyan-Q 托管。
- 旧写法 `inet4-route-exclude-address` / `inet6-route-exclude-address` 会自动合并到
  `route-exclude-address`，并去除重复条目。
- 默认 TUN 协议栈改为 `mips`（mihomo 推荐值，Windows 防火墙下比 `system`/`mixed`
  更稳定）；显式设置的 `stack` 优先。
- TUN 标量设置提前校验：`stack`、`dns-mode`、`mtu`、`gso`、`strict-route` 等类型或取值
  错误会在启动前给出明确错误，不再等内核启动失败。
- 订阅自带 `dns` 但未启用（`enable` 不为 `true`）时，TUN 不再强制劫持 DNS 并会给出
  提示；`dns` 已启用但缺少 `nameserver` 时会提前报错。
- 连接页同时显示域名和目标 IP，并在 DNS 反查 / fake-ip 连接上标记来源，搜索也支持 IP。
- YAML 编辑器会对 `tun.route-address` / `tun.route-exclude-address` 的列表项做 CIDR
  诊断，写错时直接标出位置。
- 注入 DNS 加固：只监听 `127.0.0.1:1053`；DNS 劫持同时覆盖 UDP 和 TCP
  （`any:53` + `tcp://any:53`）；补充 `proxy-server-nameserver`，避免代理服务器域名
  受普通 DNS 污染。
- 启动日志会打印 TUN 托管设置（协议栈和排除条数），并对 fake-ip 下的排除项、`/0`
  全量网段、IPv6 关闭时的 IPv6 排除项给出提示；热重载时这些提示降到 debug 级别。
- 脚本、订阅和手动配置三条路径使用同一套校验与合并逻辑。

## 使用方式

在 JavaScript 覆写脚本中：

```js
function main(config, profileName) {
    const directCidrs = [
        "175.45.34.88/32",
        "222.73.105.170/32"
    ];

    config.tun = config.tun || {};
    config.tun["route-exclude-address"] = directCidrs;
    return config;
}
```

也可以直接在配置中写（块列表、行内列表或 flow 映射均可）：

```yaml
tun:
  stack: mips
  mtu: 1400
  strict-route: true
  route-exclude-address:
    - 175.45.34.88/32
    - 222.73.105.170/32
```

## 注意

- `route-exclude-address` 只支持 IP/CIDR，不支持域名；需要按域名绕过代理时仍应使用
  `DIRECT` 规则。
- 如果订阅没有自带 `dns`，Nyan-Q 会注入 fake-ip 模式，应用拿到的域名解析结果是
  `198.18.x.x`，此时 `route-exclude-address` 只对应用直接连接 IP 的场景生效；域名流量
  仍然经过 TUN，不会命中真实 IP 排除列表。
- TUN 的 `enable`、`auto-route`、`auto-detect-interface` 和 DNS 劫持基础项由 Nyan-Q
  托管，脚本或订阅对这些字段的修改会被覆盖；其余 `tun` 键会合并保留。

## 升级说明

- 覆盖安装 `Nyan-Q-0.2.3-win64-setup.exe`。
- 升级后首次启用 TUN 可能请求一次 UAC，用于更新 Helper 版本。
- 配置、订阅和脚本保持不变。
